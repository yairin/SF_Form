# תוכנית עיצוב UI מלאה — מערכת הטפסים הדיגיטליים

עודכן: 12 ביולי 2026 · ענף: `claude/form-builder-system-kf36td` · מסגרת עדיפויות: **P0–P3** (השפעה × דחיפות)

מפת דרכים לחוויית משתמש נגישה, נייטיבית ל-Salesforce ומותאמת רשות מקומית — לתושב הממלא טופס, ולעובד המנהל, בונה ומנתח.

## איך נקבעו העדיפויות

| רמה | משמעות |
|-----|---------|
| **P0 — חסם/חובה** | נגישות רגולטורית (ת״י 5568 / WCAG AA), RTL תקין, מובייל. ללא אלה המערכת אינה כשירה לרשות ציבורית. |
| **P1 — ליבת החוויה** | משפיע ישירות על השלמת הטופס והבהירות: ולידציה, מסך אישור, קבצים, שפת עיצוב, דוחות. |
| **P2 — העשרה** | ערך גבוה שאינו חוסם: שדות מותנים, שמירת טיוטה, ערכות מיתוג, ריבוי-שפות, ניווט. |
| **P3 — משלים** | ליטוש ותוספות: אנימציות, ייצוא מתקדם, ספריית שדות, תצוגות לפי תפקיד. |

**סטטוס:** ✅ קיים · ◐ חלקי · ✦ חדש (נשלח בסשן הנוכחי) · ○ פער (עבודה חדשה). **מאמץ:** S / M / L.

## עקרונות מנחים
- **Native-first** — SLDS 2 Design Tokens & Styling Hooks במקום CSS מקומי.
- **Mobile-first** — רוב הפניות ממכשיר נייד; תכנון קודם לרוחב צר.
- **Accessibility** — מקלדת, קורא-מסך, ניגודיות, live regions כברירת מחדל.
- **Clarity** — סטטוס נקרא בצורה (צ׳יפ/פס צבע), סיכום לפני פרטים, טקסט מנקודת מבט המשתמש.

## מפת דרכים מתועדפת

**שלב 1 · P0 — כשירות ציבורית (חוסמים):** נגישות ת״י 5568/WCAG AA · RTL רוחבי · Responsive/Mobile · מצבי טעינה-ריק-שגיאה.

**שלב 2 · P1 — ליבת חוויית המשתמש:** Design Tokens + טיפוגרפיה עברית · מסך אישור + סיכום ולידציה · חוויית קבצים · גרירה-ושחרור במחולל · סינון + גרפים + KPI.

**שלב 3 · P2 — העשרה:** שדות ולוגיקה מותנית · שמירת טיוטה · ערכות מיתוג + באנר · ריבוי-שפות (ערבית) · ניווט אחוד.

**שלב 4 · P3 — ליטוש:** מיקרו-אינטראקציות · ייצוא Excel/PDF · ספריית שדות + Undo/Redo · תצוגות לפי תפקיד.

---

*כל הפריטים מתוכננים Native-first (SLDS 2, Lightning Base Components, משאבים סטטיים). פריטים המסומנים ✦ נשלחו ונפרסו לארגון בסשן הנוכחי.*
