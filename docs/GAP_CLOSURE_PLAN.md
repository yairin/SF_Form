# תוכנית סגירת פערים — טפסים עירוניים (Native-first, PSS)

מסמך זה מפרט את התוכנית להעלאת מחולל הטפסים מרמת "טופס פשוט" לרמת "טופס בקשה
עירוני" מלא (בהשראת ה-smartforms של רשויות בישראל). כל שלב נפרס דרך ה-CI ונבדק
מקצה-לקצה לפני המעבר לשלב הבא.

## עקרונות
- **Native-first**: LWC + Apex + Experience Cloud + PSS; שקילת OmniStudio לתהליכים כבדים.
- **ולידציה בשרת תמיד** (לא לסמוך על צד לקוח); הקשחת Guest.
- כל תשובה נשמרת גם ל-`Form_Answer__c` לצורך דיווח; שמירת `Response_Data__c` המקורי.
- פריסה מדורגת: כל תת-שלב = commit + bump ל-`ops/deploy.trigger` + ריצת CI ירוקה.

## גל 1 — פאריטי "בקשה בסיסית"

### שלב א׳ — ולידציה בשרת + סוגי שדה חדשים  ← מבוצע כעת
- `FormValidationService` (Apex): אימות מול סכימת התבנית — שדות חובה, פורמט
  אימייל/טלפון/מספר/תאריך, ו**ביקורת ספרת ביקורת לתעודת זהות ישראלית**.
- שילוב ב-`FormResponseController.submitResponse` — חסימת הגשה לא תקינה עם הודעות בעברית.
- סוגי שדה חדשים בבונה ובמרנדר: `idNumber` (ת"ז), `currency` (סכום ₪).
- ולידציית ת"ז גם בצד לקוח (UX) — השרת הוא הסמכות.
- בדיקות Apex: הגשה תקינה, חסימת חובה, ת"ז תקינה/שגויה.

### שלב ב׳ — העלאת מסמכים
- סוג שדה `file` בבונה; רכיב העלאה במרנדר → `ContentVersion` המקושר ל-`Form_Response__c`.
- הרשאת Guest ל-`ContentVersion` (create) + הקשחה (סוגי קובץ/גודל).
- קישור התמונות/מסמכים ברשומה למנהל.

### שלב ג׳ — אשף רב-שלבי + לוגיקה מותנית  ← הבא בתור (עדיפות המשתמש)
- סכימה מורחבת: קיבוץ שדות ל-`steps` (שלבים) עם כותרת לכל שלב; תאימות לאחור למערך שטוח.
- מרנדר Wizard עם פס התקדמות; ולידציה מצטברת פר-שלב (Next חוסם עד מילוי חובה/תקינות).
- בונה: ניהול שלבים (הוספה/כותרת/שדות בכל שלב).
- בהמשך: כללי הצגה מותנית (`visibleWhen`) ושדות מבניים (כתובת/שעה).

### שלב ד׳ — אישור והתראות
- מסך אישור + מספר סימוכין (קיים) → הוספת **אימייל/SMS** (Flow) ו-**PDF סיכום**.
- התראות פנימיות בשינוי סטטוס / חריגת SLA.

## גל AI — סוכן בדיקת טפסים חכם ("Power Agent")

מטרה: כאשר מבוקשת בדיקת AI, סוכן בוחן את ההגשה **ואת הצרופות**, מוודא התאמה לנדרש,
ואם חסר משהו — פונה **יזומה** לממלא עם קישור להשלמה. יוצר הטופס מגדיר מה ייבדק.

### רכיבי המימוש (Native-first)
1. **הגדרת ציפיות ע"י יוצר הטופס** (מודל נתונים):
   - `Form_Template__c.AI_Review_Enabled__c` (checkbox) — האם להפעיל בדיקת AI.
   - `Form_Template__c.AI_Review_Instructions__c` (long text) — מה הסוכן צריך לוודא
     (למשל: "ודא שצורף צילום ת"ז קריא ותלוש שכר מ-3 החודשים האחרונים").
   - עריכה בבונה הטפסים (סקשן "בדיקת AI").
2. **מודל תוצאה על ההגשה** (`Form_Response__c`):
   - `AI_Status__c` (Pending / Approved / Needs_Info / Error), `AI_Findings__c` (text),
     `AI_Reviewed_At__c`, `Update_Token__c` (מזהה חד-פעמי לקישור עדכון), `Update_Requested__c`.
3. **שירות הבדיקה** `FormAIReviewService` (Apex):
   - אוסף את נתוני ההגשה + טקסט הצרופות (ContentVersion) → בונה פרומפט מ-Instructions →
     קורא ל-**Agentforce/Einstein** → מקבל verdict מובנה {complete, missing[], notes}.
   - כותב את התוצאה ל-`Form_Response__c`.
4. **הרצה**: אוטומטית בהגשה כשהתבנית מסומנת ל-AI, וגם כפתור "בדוק ע"י AI" ידני.
5. **פנייה יזומה + קישור השלמה**:
   - בסטטוס Needs_Info → שליחת **אימייל/SMS** לממלא עם קישור לעמוד ציבורי שטוען את
     ההגשה לפי `Update_Token__c` ומאפשר להוסיף/להחליף צרופות ושדות חסרים.
   - לאחר עדכון → הרצת בדיקה חוזרת.

### תלויות (חוסמות)
- **צרופות**: תלוי ב**גל 1 · שלב ב׳ (העלאת מסמכים)** — חייב לקדם אותו לפני בדיקת צרופות.
- **גישת מודל**: Agentforce מופעל + רישוי, או Einstein Generative AI מופעל. **שלב אינטראקטיבי בארגון** — ילווה.
- **קריאת קבצים (OCR/PDF)**: תלוי ביכולת המודל/שירות; PDF-טקסט קל, תמונות דורשות OCR.
- **פנייה יזומה**: תשתית אימייל/SMS + עמוד עדכון מאובטח (token).

### סדר ביצוע מוצע לגל ה-AI
AI-1: מודל נתונים + הגדרת ציפיות בבונה (deployable מיידית).
AI-2: שירות בדיקה + כפתור ידני + כתיבת ממצאים (דורש גישת מודל).
AI-3: פנייה יזומה + עמוד עדכון מאובטח + בדיקה חוזרת.

## גל MT — ריבוי רשויות תחת org אחד (Multi-tenant)

לא לכל רשות יש org משלה — יש לאפשר מספר רשויות תחת org אחד, עם בידוד הרשאות וגישה.

- **MT-1 (מודל):** אובייקט `Authority__c` (רשות/דייר) + שדות config פר-רשות
  (AI_Engine/Endpoint/Model/API_Key, Public_Site_Base_Url). Lookup `Authority__c`
  על Form_Template/Form_Response/Department/Service_Type. הפנייה נחתמת ברשות של
  התבנית (בטריגר הניתוב). `FormAIReviewService` קורא config פר-רשות עם נפילה
  ל-org-default. **בוצע.**
- **MT-2 (הגדרות):** ניהול הרשויות והמפתחות דרך טאב **Authority** (רשומה לכל רשות).
- **MT-3 (בידוד גישה):** OWD=Private לאובייקטים; מיפוי משתמש→רשות (שדה על User /
  Public Group לכל רשות); **Restriction Rules** (מומלץ, נייטיב) או Sharing Rules
  כדי שכל משתמש יראה רק את נתוני הרשות שלו. *(כולל שלבים אינטראקטיביים: הקצאת
  משתמשים/קבוצות.)*
- **MT-4 (ציבורי):** כל טופס ציבורי משויך לרשות דרך התבנית; פנייה אנונימית נחתמת
  ברשות הנכונה.

## גל 2 — סקרים ותוצאות
- סוגי שאלה: דירוג (1–5), NPS, מטריצה/רשת, בחירה יחידה/מרובה.
- **טאב "תוצאות"**: רשימת טפסים → טבלת תוצאות מלאה + גרפים אוטומטיים לפי סוג שדה
  + סיכום מילולי (היברידי: חוקים + Einstein GenAI אם מופעל).
- עמידה בהיקף ציבורי גדול (בדיקת מגבלות Guest, bulk-safe).

## גל 3 — סטטוטורי מלא
- **תשלום אגרה** (סליקה) לטפסים כגון הנפקת תעודה.
- **חתימה דיגיטלית** (signature pad) + הצהרות/תצהיר.
- **מעקב סטטוס לפונה** ("איפה הבקשה שלי") — לפי מס' סימוכין + ת"ז.
- **נגישות ת"י 5568 / WCAG 2.0 AA** — ביקורת ותיקון.
- CAPTCHA/אנטי-ספאם + הגבלת קצב; שמירת טיוטות (Save & Resume).
