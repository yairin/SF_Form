# אפיון — טופס בקשת הנחה בארנונה לפי עקרון "שאל פעם אחת" (Once-Only)

> **סטטוס: אפיון בהמתנה (Design — On Hold).** אין לפתח קוד פיצ'ר עד הכרעת ה-Gateway
> להזדהות (ראה `docs/NATIONAL_AUTH.md`). מסמך זה מקבע את ההחלטות שסוכמו, כדי שהבנייה
> תתחיל מייד עם הסרת החסמים. תאריך הסיכום: 2026-08-09.

## 1. מטרה
טופס בקשת הנחה בארנונה שבו התושב מזדהה **פעם אחת** (הזדהות ממשלתית), נתוני ההכנסה
הרלוונטיים מתמלאים אוטומטית וללא אפשרות עריכה, ההשלמה הידנית מצומצמת למינימום, ההכנסות
מ-106 מסוכמות אוטומטית, מסמכי המקור מצורפים, והתושב מאשר את הבהרת הסודיות לפני שליחה.
הטופס והקבצים מועברים לרשות המקומית (מחלקת ארנונה).

## 2. שתי תלויות חוסמות (חובה לתעד)
| # | תלות | מה חוסם | סטטוס |
|---|---|---|---|
| א | **Gateway להזדהות לאומית** | *מי* התושב (ת״ז/שם/רב״א) | טרם הוכרע — **ממתינים** |
| ב | **API רשות המסים** | *נתוני ההכנסה* (106/תיאום מס/דוח שנתי) | **טרם פותח** |
> גם לאחר בחירת ה-Gateway, מילוי-ההכנסה האוטומטי ימתין ל-API של רשות המסים. שני
> החסמים בלתי-תלויים זה בזה.

## 3. החלטות שסוכמו (2026-08-09)
1. **מקור נתוני ההכנסה:** API עתידי מול רשות המסים (טרם פותח). הטופס ייבנה עם
   **נקודת-חיבור (seam) מוכנה** שתוכל להפעיל את ה-API כשיהיה; עד אז השדות ריקים/בהמתנה.
2. **מילוי אוטומטי לקריאה-בלבד:** שדות ההכנסה מתמלאים מה-API ו**נעולים לעריכה** ע"י
   ממלא הטופס. ה"נעילה" היא ב-UI; האמינות המלאה נשענת על כך שהמקור הוא ה-API הסמכותי.
3. **דוחות וסיכום:** ניתן לצרף **כמה דוחות** (106 / תיאום מס 116 / דוח שנתי 1301).
   **הסיכום האוטומטי חל על 106 בלבד** — סכימת ההכנסה החייבת על פני מספר טפסי 106
   (ריבוי מעסיקים). 116/1301 נקלטים ומצורפים אך אינם נכנסים לסכימה האוטומטית.
4. **מסמכי מקור:** הדוחות עצמם מצורפים לטופס (גיבוי לפריטי מידע שלא מולאו בשדות).
5. **הסכמת סודיות:** הטופס מציג הבהרה על חובת הסודיות החלה על המידע המועבר ומחייב אישור
   מפורש לפני שליחה; נשמר תיעוד הסכמה (חותמת זמן + גרסת הנוסח).
6. **יעד ההגשה:** רשומת `Form_Response__c` ב-Salesforce עם הקבצים המצורפים,
   **בתוספת ניתוב/התראה למחלקת הארנונה** (הקצאה/Queue/התראה למטפל).

## 4. שדות מינימליים נדרשים (טיוטה — לאישור סופי מול נוהל הרשות)
לפי סוג הדוח. הרשימה עדיין דוגמה ("לדוגמה" במקור) וטעונה אישור מקצועי:

- **טופס 106:** הכנסה חייבת · מספר מעסיקים. *(שדות אלה נכנסים לסכימה.)*
- **תיאום מס (116):** הכנסה משכר עבודה · קצבת פנסיה · הכנסה מעסק/עצמאי · הכנסה משכירות ·
  רווחי הון · מקור אחר.
- **דוח שנתי (1301):** הכנסה משכר עבודה · קצבת פנסיה · הכנסה מעסק/עצמאי · הכנסה משכירות ·
  רווחי הון · מקור אחר.

## 5. זרימת המשתמש (Flow)
1. כניסה + הזדהות ממשלתית **פעם אחת** דרך ה-Gateway → זהות מאומתת מגיעה לטופס בטוקן חתום.
2. הטופס מפעיל את ה-API של רשות המסים (כשיהיה) וממלא את שדות ההכנסה **לקריאה-בלבד**.
3. התושב בוחר/מצרף את סוגי הדוחות הרלוונטיים ומעלה את מסמכי המקור.
4. **סכימת 106 אוטומטית** של ההכנסה החייבת על פני כל טפסי ה-106.
5. הצגת הבהרת הסודיות → **אישור חובה**.
6. "שלח" → יצירת `Form_Response__c` + קבצים מצורפים + ניתוב/התראה למחלקת הארנונה.

## 6. אבטחה (הנחיה 5.35 — חובה)
- **סריקת נוזקות** לכל קובץ מצורף לפני קליטה.
- **הצפנת Shield** ל-PII: ת״ז ונתוני הכנסה.
- **Least privilege / FLS·CRUD** (`WITH USER_MODE`) בכל גישה לנתונים; משתמש Guest לטופס.
- **סודות ב-Named Credential** (מפתח/סוד ה-API של רשות המסים ושל אימות הטוקן) — לא בקוד.
- שדות ההכנסה נעולים לעריכה בצד השרת, לא רק ב-UI.
- תיעוד הסכמת סודיות עם חותמת זמן וגרסת נוסח.

## 7. רכיבים לבנייה (כשהחסמים יוסרו)
בלתי-תלוי ב-API-ים (ניתן לבנות ראשון לאחר הכרעת ה-Gateway):
- תבנית הטופס במחולל הקיים · העלאת קבצים + סריקת נוזקות · סכימת 106 · הבהרת סודיות +
  תיעוד הסכמה · ניתוב/התראה למחלקת הארנונה.

תלוי-חסמים:
- **תלוי Gateway:** שער הכניסה/הזדהות + מילוי-מוקדם ונעילה של שדות הזהות.
- **תלוי API מס:** משיכת נתוני ההכנסה ומילוי השדות לקריאה-בלבד.

## 8. פריטים פתוחים להכרעה לפני בנייה
1. הרשימה הסופית והמדויקת של שדות המינימום לכל סוג דוח (סעיף 4).
2. הנוסח המשפטי המדויק של הבהרת הסודיות + מי מאשר אותו.
3. אילוצי קבצים: סוגים מותרים, גודל מרבי, מספר מרבי.
4. כללי סכימת 106: שם השדה המדויק ("הכנסה חייבת") וכללי מניעת כפילות בין מספר 106.
5. יעד הניתוב המדויק בתוך Salesforce: Queue / משתמש / מחלקה + סוג ההתראה.
6. חוזה ה-API של רשות המסים: claims/שדות, אימות, TTL — כשייקבע.
